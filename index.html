The problem

Visual question answering (VQA): image + question → short answer.

Each example is a 224×224 photo and a natural-language question such as “What colour is the bus?”, “How many people are there?” or “Is the man wearing a hat?”. Your model returns a short answer (red, 3, yes). Ten people answered every question, and your answer is scored against all ten.

You train on train and choose your model on val. You never see the test set. You upload your code + weights, and Codabench runs them on the hidden test images.

What you need

Everything runs on free tools.

  • Your BITS Google account. The student package link opens only for BITS IDs.
  • Google Drive space: the package is 384 MB. A typical team uses 1–3 GB in total. The free 15 GB is plenty.
  • Google Colab (free tier, T4 GPU) for training. Training the baseline takes about 10 minutes.
  • A Codabench account (codabench.org), one per team. Register for the competition; the instructor approves registrations.
  • Basic PyTorch. The package has a complete working baseline to start from.
  • The Colab buttons open the notebooks from this site, but the notebooks read the data from your Drive, so upload the package to MyDrive/vqa_datathon first (step 2).

Step by step

From zero to a scored submission.

  1. Form your team and register

    Your datathon team is your course project team. Create one Codabench account for the team, open the competition page and click Register. Wait for approval.

  2. Get the student package

    Download student_package.zip (BITS login), unzip it, and upload the student_package folder to your Google Drive as MyDrive/vqa_datathon. It contains the train/val data, the baseline (code + trained checkpoint), the official evaluator, the complexity counter, the submission checker and two Colab notebooks. Read its README.md.

  3. Run the baseline

    Open the baseline notebook in Colab with the button below, or open notebooks/student_baseline.ipynb from your Drive with Colab. Choose a T4 GPU runtime and run all cells. Use File → Save a copy in Drive to keep your own edits. The first cell installs the exact library versions Codabench uses. You should get about 46.2 val accuracy, 18.15 M parameters and 3.69 GFLOPs.
    CO Open baseline notebook in Colab ↗

  4. Improve it

    Edit baseline/simple/model.py or write your own model.py. Try better image or text encoders, attention and fusion, answer-space tricks or training tricks. Keep an eye on size and FLOPs, because they cost points (see Scoring). Use eval/vqa_eval.py on val to measure accuracy and eval/complexity.py for params and FLOPs.

  5. Build and check your submission

    Run notebooks/make_submission.ipynb. It zips model.py + checkpoint.pt + helper files and then runs the same program Codabench runs on 2,000 val questions, on CPU, and prints any error in full. It also reports your val score, params, FLOPs, the estimated test runtime and the zip's SHA256.
    CO Open submission notebook in Colab ↗

  6. Submit on Codabench

    Upload submission.zip under My Submissions. Check that Status = 0. Codabench does not show logs, only a status code (see Limits & tips). Pick which of your submissions is shown on the leaderboard: that one is your entry.

  7. Keep improving until the deadline

    Up to 3 submissions per day. The leaderboard shows your score on a public part of the test set. Submissions close Thursday 26 November 2026, 23:59 IST.

  8. Test day

    Date to be announced. Bring your team; your leaderboard submission is run and checked live (see Timeline).

The model interface

Fixed for everyone. Codabench calls exactly this.

model = build_model()                                   # defined in your model.py
model.load_state_dict(torch.load("checkpoint.pt", map_location="cpu", weights_only=True))
answers = model.predict(images, questions)
#   images    : FloatTensor[B, 3, 224, 224], RGB, values in [0, 1], NOT mean/std-normalised
#   questions : list[str]  (raw text; use any tokenizer inside your model)
#   returns   : list[str]  (one lowercase answer per question)
  • build_model() must work offline. All weights come from checkpoint.pt. Ship vocabularies and other small files next to model.py and read them relative to __file__ (the baseline shows how).
  • Codabench environment (CPU only): python 3.10, torch 2.14.1, torchvision 0.29.1, transformers 5.20.2, pillow 12.3.0, numpy 2.2.6, pyyaml. No other packages, and no internet.

Scoring

Accuracy minus a price for size and compute.

Score = Acc − 2·log₂(Params / 18,154,866) − 2·log₂(FLOPs / 3,688,267,776)
  • Acc: official VQA accuracy, in %. Answers are normalised (punctuation, number words → digits, articles), and each question scores min(#humans who gave your answer / 3, 1), averaged over leave-one-out subsets of the 10 human answers. Answer in lowercase.
  • Params: sum(p.numel() for p in model.parameters()). All parameters count, frozen pretrained backbones included.
  • FLOPs: PyTorch FlopCounterMode around one predict() call with batch size 1 and a fixed dummy image and question, on CPU, torch 2.14.1. One multiply-add = 2 FLOPs. Matmul, convolution and attention are counted; element-wise ops are not.
  • The reference values are the baseline's. Every doubling of params costs 2 points, and so does every doubling of FLOPs. Halving either gains 2 points.

Rules

  1. Inputs: only the image tensor and the question text, through the interface above.
  2. Training data: train and tune only on the provided train and val sets. Do not use any other image question–answer annotations.
  3. Pretrained models: generic pretrained backbones are allowed, for example ImageNet classifiers, CLIP-style image/text encoders and BERT-family language models. Their parameters and FLOPs count toward your score. Models trained or fine-tuned for visual question answering, or on any image question–answer data, are not allowed.
  4. Offline inference: no network access, external APIs or downloads at inference. All weights must be in your checkpoint.
  5. No shortcuts: do not try to read, store or transmit test data, and do not hard-code or look up answers. The model must answer from the image and the question.
  6. Teams: your course project team, one Codabench account per team.
  7. Frozen entry: your leaderboard submission (zip + SHA256) is final. On test day it is run from that same zip.
  8. Academic integrity: the BITS Pilani academic integrity policy applies.

Tips

  • Always run make_submission.ipynb before uploading. It runs the same code as Codabench and shows the full error.
  • Output lowercase answers. If all 10 humans wrote yes, then Yes scores 0.
  • Keep the Drive copy of the package and your best checkpoint, not one per epoch.
  • Don't leave your first submission to the last day: Codabench queues can be slow near deadlines.

FAQ

Can I use a pretrained CLIP / ResNet / BERT?

Yes, any generic backbone that was not trained for VQA. Its parameters and FLOPs count toward your score, so a frozen backbone is not free.

Do I have to use the 1,000-answer vocabulary?

No. answers.txt is just the baseline's answer space. Any approach that returns answer strings is fine.

Can I train on val as well?

Yes, train and val are both provided data. But you then lose your only local estimate of test accuracy.

My submission works in Colab but fails on Codabench.

Run make_submission.ipynb: it runs on CPU with the Codabench program. Common causes are a package missing from the environment, files read from outside the model folder, a GPU-only call, or answers that are not strings.

Does a top Codabench rank guarantee top marks?

No. See the note in Timeline. Marks depend on test-day verification of your leaderboard submission.
